# Development Diary - October 2026

## 2026-10-08: Reproduced and repaired launcher compilation failure

Built the Android Java shell locally using JDK 17, Gradle 8.9, Android SDK 35,
and SDL 3.4.2's staged/patched Java glue. The compiler found APK-update helper
methods inserted inside `SetupActivity.onCreate`, a duplicate static guard,
and `ContextCompat` imported from `androidx.core.app` instead of `.content`.
Removed the redundant update implementation embedded inside onCreate and its
competing automatic check; the existing `ApkUpdateManager` flow retains the
Updates card, progress/status, pending-install resume, and single automatic
check per process. Corrected the import and duplicate declaration.

`compileDebugJavaWithJavac` and `assembleDebug` both succeeded. This assembly
validated Java/resources/DEX/signing only: no freshly built native game libraries
were staged, so the resulting shell APK is not a playable game and is not shipped.
Both native engines subsequently built successfully; see the packaging entry below.
No Actions run was started.

## 2026-10-08: Recoverable pathfinding queue saturation

Continued from `99c148e47c48554c5ca6b1c7c321c678f5cce4aa` on
`abodeh-play-worker-v2`. The 512-slot ring holds 511 requests. All four request
modes ignored a failed admission; the timed retry also cleared its deadline
unconditionally. Removed the fatal queue-full diagnostic and made both games
retry through their existing AI scheduler one logic frame later. Failed timed
retries retain a deadline and cap the returned sleep, even inside AI update.
Cancelled requests clear their deadline; deleted objects are skipped at drain.
Added profiler counters without adding snapshot/CRC fields or changing the
5000-cell budget, queue size, or tick rate.

Production-code regression fixture passed for both games, including repeated
1000/2000-unit bursts with identical execution order, a 500-unit burst,
wraparound, duplicate requests, repeated saturation, sleeping AI, cancellation,
and deleted objects. Built with ASan and UBSan; leak detection was disabled
because this execution environment cannot inspect the process task directory.
This fixture does not validate native engine compilation or phone gameplay.

Android Build #65 (`37627614363`) completed native build and verification but
failed packaging. Device/replay/paired multiplayer validation is still required. No Actions workflow was dispatched.

## 2026-10-08: Worker5 dual-engine local build

Built the 30 Hz and 60 Hz Android engines locally from identical source changes
with NDK 27.2.12479018 and packaged worker5 (versionCode 10310). Retained
separate native symbols before stripping; DXVK binaries remain unstripped.
The committed signing key is unchanged. Shallow checkouts must supply a
verified positive `GX_ENGINE_BUILD_NUMBER` instead of embedding their truncated
commit count, which could let an older downloaded engine supersede this fix.
Packaging uses the verified full-history count 3189 for this third PR commit.

Full native compilation does not establish device performance, replay
compatibility, or multiplayer determinism. Those checks remain pending.

`068e04a287e382506942a4fd2e88d3173e5b0c5d5da94c0072a007e7a3075c10`.
Verified v2 signing against the committed keystore, package/version metadata,
all 17 AArch64 runtime libraries and their non-system DT_NEEDED dependencies,
both engines against their captured binaries, unchanged DXVK binaries, and
engine build marker 3189. An incremental shell-only result was rejected during
inspection; a clean assembly produced the verified APK. Packaging now checks
every staged native library is actually present before reporting success.
