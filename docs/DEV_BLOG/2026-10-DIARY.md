## 2026-10-16: Restore subscription launcher compilation

Build Android #67 passed CMake, native compilation, artifact verification and
symbol stripping, then failed in `Package APK`. Reproducing the Android shell at
`8940f5ac6d28fdf7625ebc0b9b1a9b936b4344e9` with Gradle 8.9, AGP 8.5.2,
JDK 17 and SDK 35 exposed three `cannot find symbol: BuildConfig` errors in
`SubscriptionApi.java` (lines 48, 55 and 72).

AGP 8 does not generate `BuildConfig` by default. The subscription client reads
`BuildConfig.VERSION_NAME` for request metadata, so the app module now explicitly
enables generation with `buildFeatures.buildConfig`. The existing version-name
defaults and manual version overrides continue to supply the generated value.

The packaging step now captures stdout and stderr in `logs/package_android.log`,
which the existing always-run build-log upload includes even after a failure.
`pipefail` preserves the packager's failure status. Gradle also emits a plain
console log and a stack trace on failure.

Validation: the unchanged shell failed with exactly those three compiler errors;
the corrected shell passed `:app:compileDebugJavaWithJavac` and generated
`VERSION_NAME = "1.3.0-abodeh1"`. Shell syntax, workflow YAML and a deliberate
failing log pipeline were checked; the pipeline retained stderr and exit code 7.
The actual `package-android-zh.sh` also passed `assembleDebug` using the real native
payload from committed reference APK blob `034a2c9ca1d2bc3a8a70866569512b1415e9a89b`.
That packaging-only check reused existing engines; it is not a newly compiled
cross-play APK or an on-device multiplayer test. The packaged APK passed signature,
ZIP integrity and `libmain.so` runtime-dependency checks.
No engine, simulation-rate or reference-math code changed in this fix.
